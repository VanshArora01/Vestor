# DATA_MODEL.md — Vestor

Single source of truth for the schema. Before adding a table or column anywhere, check this file first — if the entity already exists here, extend it, don't recreate it (see DECISIONS.md — Emergency Fund).

Each table is tagged with the phase it belongs to (ROADMAP.md). Do not build a later-phase table early just because it's easy — schema for unbuilt features tends to drift from what actually gets used.

## Cross-cutting notes

- **Financial Context Service** doesn't own its own tables — it reads/aggregates from `transactions`, `goals`, `portfolio_holdings`, and `user_academy_progress` at query time (or via a materialized view later if performance demands it). Don't create a separate "aggregated_data" table that duplicates what's computable from source tables — that's the exact duplication this schema is designed to avoid.
- **Every table above has `user_id`** except global seed data (`categories` where `is_custom = false`, `academy_modules`, `quiz_questions`, `badges`) — reinforces the single-user isolated profile decision.
- Add new tables here before creating them in migrations. If a migration needs a table not listed here, stop and add it to this doc first — that's the whole point of this file.
